# Plan 07-04: User Affordances

## Goal
Implement OPS-22 and OPS-23: flag source and report error controls on story pages.

## Requirements
- OPS-22: Reader can flag a source from any story page; flagged content enters review queue without publishing
- OPS-23: Reader can report a factual error on story; report enters corrections queue producing dated correction note

## Tasks

### Task 1: Flag source control (OPS-22)
- [ ] Create `apps/site/src/components/FlagSource.astro`
- [ ] Add to story page below sources list
- [ ] Form: reason dropdown, optional comment
- [ ] Submit to `/api/reports/flag` endpoint
- [ ] Store in D1 reports table with status=pending
- [ ] Create admin page to review flags
- [ ] Add tests for flag form and API

### Task 2: Report error control (OPS-23)
- [ ] Create `apps/site/src/components/ReportError.astro`
- [ ] Add to story page near bottom
- [ ] Form: error type dropdown, description, evidence URL
- [ ] Submit to `/api/reports/error` endpoint
- [ ] Store in D1 reports table with status=pending
- [ ] When approved, add dated correction note to story
- [ ] Create admin page to review reports
- [ ] Add tests for report form and API

### Task 3: Reports database schema
- [ ] Create migration `shared/db/016_reports.sql`
- [ ] Tables: reports (id, type, story_slug, status, data, created_at, reviewed_at)
- [ ] Add seed data for testing
- [ ] Run migration locally

### Task 4: Admin review interface
- [ ] Create `apps/site/src/pages/admin/reports.astro`
- [ ] List pending reports with story context
- [ ] Actions: approve, reject, mark as reviewed
- [ ] When approved, write correction note to R2
- [ ] Protect with basic auth

### Task 5: Correction notes
- [ ] Create correction note format (MDX)
- [ ] Store in R2 under `corrections/{slug}.mdx`
- [ ] Display on story page when correction exists
- [ ] Add to snapshot if needed

## Files to Create/Modify

## Success Criteria
- Reader can flag source from story page
- Flag enters review queue, doesn't publish
- Reader can report factual error
- Report enters corrections queue
- Approved reports produce dated correction notes
- Admin can review and act on reports
