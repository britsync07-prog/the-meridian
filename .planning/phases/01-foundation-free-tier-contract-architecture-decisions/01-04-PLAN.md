<objective>
Create the R2 bucket and its two prefix-scoped lifecycle rules, stand up the eight-project static shard that D-06 makes mandatory infrastructure, and record the delivery model in an ADR.

Purpose: Two decisions in this plan are expensive to get wrong and cheap to get right now. First, R2's lifecycle rules are the only mechanism that keeps the bucket inside the free allowance — Cloudflare's own budget alerts are informational and do not cap spend — and a rule with an empty prefix would expire the Open Graph images and the bucket root, destroying a permanent story URL's image. The prefix-scoped rule set plus a live verification script makes that failure impossible by construction rather than by care. Second, because D-05 removes the paid escape hatch entirely, the request ceiling is a permanent wall, which makes the eight-project static shard mandatory infrastructure rather than an optimisation. Building it in this phase, with the route table and the splitter, is what lets the site shed load by promoting hot stories into the static tier without a rewrite later.

Output: A live R2 bucket with exactly two prefix-scoped lifecycle rules and a verification script that proves it; eight shard project configurations plus the route table, the build-time splitter and the deploy script; and the delivery-model ADR.
</objective>

<interfaces>
The verified Wrangler command surface this plan depends on:

```
npx wrangler r2 bucket create <BUCKET>
npx wrangler r2 bucket lifecycle add <BUCKET> <NAME> <PREFIX> --expire-days <N>
npx wrangler r2 bucket lifecycle list <BUCKET>
npx wrangler r2 bucket lifecycle remove <BUCKET> --name <NAME>
```

`<PREFIX>` is the prefix condition. **Leaving it empty means "all prefixes"** — which is exactly the MED-08 failure mode. Every rule this project creates therefore carries an explicit, non-empty prefix.

The eight-shard route table (D-06), one locale prefix per shard:
| Shard | Project name | Zone route pattern | Serves |
|-------|--------------|--------------------|--------|
| 01 | meridian-static-uk | `<zone>/uk/*` | `/uk/` |
| 02 | meridian-static-us | `<zone>/us/*` | `/us/` |
| 03 | meridian-static-au | `<zone>/au/*` | `/au/` |
| 04 | meridian-static-ca | `<zone>/ca/*` | `/ca/` |
| 05 | meridian-static-ie | `<zone>/ie/*` | `/ie/` |
| 06 | meridian-static-nz | `<zone>/nz/*` | `/nz/` |
| 07 | meridian-static-in | `<zone>/in/*` | `/in/` |
| 08 | meridian-static-in-hi | `<zone>/in-hi/*` | `/in-hi/` |

The global surfaces (`/`, `/topic/*`, `/entity/*`, `/sitemap*`, `/rss/*`, `/robots.txt`, fonts, CSS, JS — roughly 45 files) are DUPLICATED into every shard's output directory, so whichever project's route receives the request, the file is present. That is about 360 files against a 160,000-file budget and it removes every cross-project dependency from the static tier.

CRITICAL CONSTRAINT: no shard config, script or ADR in this plan may contain a bare ceiling literal such as `20000` or `100000`. Those values live only in `config/free-tier-limits.json` (plan 01-03) and the scan test in that plan will FAIL the build if they appear anywhere else. Reference the ceiling by its id — for example `static_asset_files_per_project` — not by its number.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| lifecycle rule → stored objects | A rule silently deletes objects in the bucket, including objects a permanent URL depends on |
| shard route → static tier | A route change sends a reader's request to the wrong project |
| Cloudflare account → billing | The account has a card on file (D-01); R2 is metered and suspends on overage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | D | R2 lifecycle rules | mitigate | A lifecycle rule with an EMPTY prefix matches every object, which would delete the `og/` images and the site root and permanently break story URLs. Every rule is created with an explicit prefix, the creator script throws if it would ever pass an empty one, and `verify-lifecycle.mjs` fails the build if any live rule has an empty or unapproved prefix. |
