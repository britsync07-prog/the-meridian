<objective>
Land the D1 schema, the seed, and the single repository module through which every datastore access must pass — and prove, on an empty database, that changing the database identifier is a configuration change rather than a code change.

Purpose: D1 is the system of record, and D1 bills the rows a query *scans*, not the rows it returns. That single fact decides the whole shape of the data layer: every filtered column needs an index, `SELECT *` is forbidden, and there must be exactly one place where SQL exists so the query surface can be audited once rather than hunted for across the codebase. The repository module (OPS-14) is what makes the no-shard topology affordable later — sharding, if it ever happens, is a routing change rather than a rewrite — and it is why the database identifier has to be a configuration value from day one.

Output: `shared/db/0001_init.sql` and `shared/db/seed.sql`; `apps/worker/src/db/repository.ts` as the only module with SQL; `apps/worker/wrangler.jsonc` carrying the bindings; two verification scripts; and the D1 topology ADR.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| code → D1 | Every statement the application issues against the datastore crosses this boundary |
| local config → live database | The `database_id` in `wrangler.jsonc` decides which database the Worker and the migration tool both talk to |
| seed → registry | Seeded rows become the feed registry that a later phase fetches from |
