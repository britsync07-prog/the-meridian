<interfaces>
The excerpt budget, exactly as PROJECT.md states it:
- at most 50 words AND at most 320 characters, whichever binds first
- at most 2 sentences
- at most 30 percent of the source article's visible text
- a source article shorter than 160 words publishes NO excerpt at all
- truncation is a hard cut at a word boundary with a visible ellipsis
- transformation is NONE: verbatim or omitted, never paraphrased, synonymized or translated

Decided contract shape (OpenCode's discretion, recorded in 01-RESEARCH.md section P7):
```ts
export const EXCERPT_BUDGET = {
  maxWords: 50,
  maxChars: 320,
  maxSentences: 2,
  maxSourceShare: 0.30,
  minSourceWords: 160,
  ellipsis: '…',
} as const;

export interface ExcerptInput {
  candidate: string;          // the publisher-supplied summary/description, verbatim
  sourceVisibleText: string;  // the publisher article's visible text
}
export type ExcerptRejection = 'source_absent' | 'source_too_short';
export interface ExcerptResult {
  text: string | null;        // null => publish NO excerpt
  truncated: boolean;
  rejection: ExcerptRejection | null;
  wordCount: number;
  charCount: number;
  sentenceCount: number;
  sourceShare: number;
}
export function applyExcerptBudget(input: ExcerptInput): ExcerptResult;
export function assertExcerptWithinBudget(text: string, sourceVisibleText: string): void;
```

   - validate the result shape with Zod 4.6.7 (`z.object({...})`) so the contract's own output is checked at runtime, not only in tests

   The algorithm, in this exact order:
   1. If `sourceVisibleText.trim()` is empty → return `{ text: null, truncated: false, rejection: 'source_absent', wordCount: 0, charCount: 0, sentenceCount: 0, sourceShare: 0 }`.
   2. Count the source's visible-text words. If that count is LESS THAN 160 → return `{ text: null, truncated: false, rejection: 'source_too_short', ... }`. Publish no excerpt at all.
   3. `allowedWords = Math.min(EXCERPT_BUDGET.maxWords, Math.floor(EXCERPT_BUDGET.maxSourceShare * sourceWordCount))`. The word cap is applied FIRST because a word-boundary cut is the only cut that can guarantee the word cap; the character and sentence caps are applied afterwards.
   4. Cut the candidate to at most `allowedWords` words, at a word boundary. Never mid-word.
   5. Cut to at most `EXCERPT_BUDGET.maxSentences` sentences. A sentence boundary is `.`, `!` or `?` followed by whitespace or end-of-string.
   6. Cut to at most `EXCERPT_BUDGET.maxChars` characters, at a word boundary.
   7. If any cut removed content, append the visible ellipsis `…` (U+2026), and ensure the FINAL string including the ellipsis is still at most `maxChars` — if adding the ellipsis would exceed the character cap, drop one more word and retry.
   8. Trim trailing whitespace before appending the ellipsis, so the output never contains a space before it.
   9. Compute `wordCount`, `charCount`, `sentenceCount` and `sourceShare = wordCount / sourceWordCount` from the FINAL text (the ellipsis is not a word).
   10. `truncated` is true if any cut happened.

   **Verbatim guarantee:** the function only ever TRUNCATES. It never rewrites, paraphrases, synonymizes or translates. The result is a prefix of the candidate plus the optional ellipsis. This is the mechanism that satisfies CON-04 and it must be directly testable.

   **Never per-source override.** There is no override parameter and no config-driven variant. A comment must say why.

**`docs/adr/0003-image-permanence.md`** — Status Accepted, Date 2026-10-20, headings Context / Decision / Consequences / References.
- **Context.** R2 storage crosses the free allowance around month 14 without a lifecycle rule. A story's URL is permanent, so its page must never show a broken image. R2's lifecycle rules delete objects silently: nothing tells the application that an image expired, and the story page's HTML was rendered months earlier pointing at it.
- **Decision.**
  - D-15: every media object expires on the SAME 12-month clock. No exemptions, no curated permanent set, no second rule to reason about.
  - D-16: an expired image renders a **silent typographic panel** carrying the headline's opening words. It reads as a deliberate design element — a classified ad or a pull-quote — not as an error. There is NO "image archived" caption, NO broken icon and NO visible system explanation. The panel's visual specifics are Phase 4's, inside the broadsheet design system.
  - D-17: BOTH mechanisms apply. (a) **Resolution at serve time** — the image URL resolves through the edge, checks R2, and returns the typographic panel when the object is gone; the stored HTML never changes. (b) **A periodic sweep** — a job finds stories whose media object has expired and re-renders just those pages, so the common case never pays a lookup.
  - D-18: the serve-time check costs **one extra R2 Class B read per image view**. That cost is accepted and is charged against the `r2_class_b_ops_per_month` ceiling in `config/free-tier-limits.json`.
  - D-19: Open Graph images never expire and are excluded from every lifecycle rule, alongside the site root.
- **Consequences.** Phase 5 implements the serve-time resolution; Phase 7 implements the sweep. Phase 1 owns the CONTRACT: `shared/templates/typographic-fallback.ts` (the pure string builder) and `shared/contract/image-permanence.ts` if the executor chooses to split the resolution rule out of the template module — the rule is: `resolveMediaObject(key)` returns `present` or `expired`, and `expired` renders the typographic fallback. The R2 lifecycle rule that enforces the 12-month clock is scoped to `media/` only and is created in plan 01-04.
