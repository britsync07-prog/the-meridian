<objective>
Build the CI feed normalization engine: parse RSS 2.0, Atom 1.0, and RDF raw snapshots using `fast-xml-parser` (5.11.2), implement dual-identity deduplication (stable GUID vs SHA-256 canonicalized URL), extract candidate media enclosures while discarding tracking pixels, and enforce per-run backlog caps.

Purpose: Feed dialects vary widely across publishers and countries. The CI pipeline normalizes these diverse structures into a unified, predictable `RawItem` schema, neutralizing oscillating publisher GUIDs and filtering outdated backlog items without risking edge Worker CPU budgets (ING-08, ING-09, D-10, D-20 to D-25).

Output: Tested parsing and normalization modules capable of converting arbitrary valid XML feeds into canonical `RawItem` records with stable identities and sanitized media enclosures.
</objective>

   - Implement `canonicalizeSourceUrl(rawUrl: string): string`:
     * Parse via `new URL(rawUrl)`.
     * Set `protocol = 'https:'`.
     * Lowercase hostname and remove leading `www.`.
     * Remove hash.
     * Strip tracking parameters: `utm_*`, `ref`, `ref_src`, `fbclid`, `gclid`, `cmp`, `at_*`.
     * Sort remaining query parameters.
     * Normalize path (remove trailing slash unless root `/`).

2. Create `src/ingest/identity.ts`:
   - Implement `resolveItemIdentity(item: { guid?: string; link: string }, options?: { forceUrlIdentity?: boolean }): string`:
     * If `options?.forceUrlIdentity` or GUID is empty/absent:
       compute `url:${sha256(canonicalizeSourceUrl(item.link))}`.
     * Otherwise return `item.guid.trim()`.

3. Create `src/ingest/media.ts`:
   - Implement `extractMediaEnclosure(item: any): { imageUrl: string | null; imageCredit: string | null }`:
     * Cascade:
       1. `<media:content>` / `<media:thumbnail>`: select image medium with highest width attribute.
       2. `<enclosure>`: if type starts with `image/`, extract `url`.
       3. Inline `<img>` in content/description: match first tag with explicit width ≥400 or without explicit small width.
     * Filter tracking pixels: reject if dimensions <200px or URL matches tracking domains (`feedburner`, `pixel.gif`, `stats.`).
     * Sanitize URL: force https, remove query tracking params. If invalid, return `null`.
     * Credit: extract from `<media:credit>`, `<media:copyright>`, or `<dc:creator>`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Publisher XML → CI Normalizer | Malformed XML, XXE injection attacks, circular entity expansion |
| Publisher HTML Content → Plaintext | Cross-site scripting (XSS), script injection in titles or descriptions |
| Publisher Metadata → Timestamps | Future-dated or manipulated pubDates skewing curation ranking |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-08 | T | `src/ingest/parser.ts` | mitigate | XML Entity Expansion / XXE attack from untrusted publisher XML (ING-08). Mitigate by using `fast-xml-parser` with pure JS parsing, no native XML entity resolver, and entity decoding limited to standard character entities. |
| T-02-09 | T | `src/ingest/url.ts`, `src/ingest/identity.ts` | mitigate | Tracking token oscillation creates duplicate cluster entries (ING-09, P-6). Mitigate by stripping all query tracking parameters in `canonicalizeSourceUrl` and hashing canonical URL. |
| T-02-10 | T | `src/ingest/normalizer.ts` | mitigate | Sybil attack or feed manipulation using future pubDates to artificially boost trending score (D-25). Mitigate by clamping any timestamp >1 hour in future to current system time. |
| T-02-11 | I | `src/ingest/media.ts` | mitigate | Publisher tracking pixel (1x1 gif) logged as story hero image (D-20). Mitigate by filtering out images with width <200px or URLs matching tracker patterns. |
</threat_model>
